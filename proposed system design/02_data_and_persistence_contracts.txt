Narration

This is a theoretical design. It assumes that LIMITATIONS.md and the source nuances listed in Phase 1 have already been addressed. Phase 2 does not refit the science. It specifies how a corrected result becomes immutable: run metadata, versioned policies, functional identity strings, transactional publication, content hashes, and explicit stage states.

The portfolio dashboard cache and stdout are not this contract. results/dashboard_cache and a regular expression over printed pounds are assumed retired as a publication mechanism before this phase is treated as the system of record.

Assumptions taken as already addressed

The Phase 1 catalogue is the only set of functional codes. E, F, H, and J have identity strings. G and K are not_requested in the first release. I is withheld below 50 excesses. A withheld value is null. There is no total. Gross and netted are different rows. The second factor of margin does not exist. Holding, when stored, uses holding_day_count and is zero on fulfilled lines. The golden comparison is value_hex, not a rounded pound from results/expected_result.txt.

Scope

In scope: the relational mart, the artifact hash rule, policy versions and signatures, stage and run enums, and the publication transaction.

Out of scope: HTTP routes, the orchestrator, authentication, warehouse ports, and the client. Phase 3 reads this schema. It does not redefine it.

Enums

Four enums. They are not interchangeable. unidentified is a functional status and a fit-artifact flag. It is not a stage status.

| Enum | Values |
|---|---|
| Stage | ok, degraded, blocked, failed, skipped |
| Run | queued, running, publishing, published, blocked, failed |
| View | published, blocked, failed, skipped |
| Functional | ok, degraded, withheld, not_requested, unidentified |

Run transitions: queued to running when a worker takes the lease; running to publishing when publication starts; publishing to published, blocked, or failed inside the publication transaction. blocked and failed are terminal. Nothing returns a run to queued.

Horizons in the first release, and no others: E, F, G, H, K are annual; I is daily; J is stress_252. A later window refit, if built, uses functional code I_WINDOW and horizon window. It is not a row this schema accepts until a later migration.

Identity text, so the column stays not null:

| Functional status | identity |
|---|---|
| ok or degraded | The formula string for that code |
| withheld | withheld:<reason> |
| not_requested | not_requested |
| unidentified | unidentified |

A failure before the loss identity writes the terminal run row and no functional rows. A control block after the view has a loss identity writes one null withheld row per requested code. Omitted codes stay not_requested.

Run status across two views: published if at least one requested view published; blocked if none published and at least one view is blocked; failed if every requested view is failed. Gross can be published while netted is blocked. Per-view reason lives on view_result.

Reason catalogue stored as an enum, not free text. Accept-path reasons, which Phase 3 emits and this schema must already allow: RUN_CAPACITY, MART_UNAVAILABLE, RUNNER_UNAVAILABLE, IDEMPOTENCY_CONFLICT. Run, view, or functional: CANCEL_LEDGER_MISSING, DRAGON_RULE_UNSET, CLOCK_PAIR_UNSET, TIMEZONE_UNSET, WINDOW_NOT_CLOSED, RESTORE_RESUBMIT, MISSING_CYCLE_TIME_CLOCK, KPI_SNAPSHOT_MISSING, RECONCILE_FAILED, COVERAGE_BELOW_FLOOR, SNAPSHOT_TOO_LARGE, CORE_COLUMN_MISSING, ZERO_DRAGONS, CV_UNDEFINED, NO_MATCHES, NO_SYNTHETIC_ATTAINMENT, WORKER_LOST, WAREHOUSE_UNAVAILABLE, ARTIFACT_STORE_UNAVAILABLE, FX_EXCLUDED_BELOW_FLOOR, SERIES_TOO_FINE, BREACH_MINUTES_UNCONFIRMED, NO_OBSERVED_SURGE_FEATURE, GPD_FIT_FAILED, XI_GE_ONE, NO_KALMAN_ESTIMATOR.

ZERO_DRAGONS and NO_KALMAN_ESTIMATOR are not how the first release labels G. First-release G is not_requested. Those reasons exist so a later release has a legal value.

Policy

A run binds policy_version. loss_definition, report_currency, and every other science field live on the policy row. They are not caller overrides.

POST of a policy inserts a draft. The document is immutable after insert. A signature inserts one policy_signature row. The only later mutation of a policy row is status: draft to active, and the previous active row to retired, in the same transaction as the signature that completes the set. A retired row does not change. A change of any field is a new policy_version.

Every field has exactly one signature role: kpi_owner, risk_engineer, or commercial_owner. Activation requires all three. A role whose fields did not change sends an explicit copied-forward signature. The bootstrap migration inserts pol-2026-10-01 as active, with three signature rows, signed_by = bootstrap, copied_forward_from null. That migration is not a human approval of open questions. Human approval of the loss definition and intended use is Phase 6.

Artifact hashes

Workers and later stages read hashes. They do not read a mutable latest key. input_hash is the SHA-256 of the canonical encoding of stage name, exposure view, mode, sorted unique site_ids, policy version, input content hashes, seed, and the pure-function version. Mode and site set are inside the hash, so a synthetic artifact cannot satisfy an observed stage.

Content hashes are not hashes of Parquet footers. Writer version and file timestamps must not change the hash. The hashed bytes are the schema (column name and dtype, in column order), then for each column the little-endian raw values after a stable sort on the artifact primary key. Snapshot key: site_id, order_line_id. Daily panel key: business_date. No statistics block and no created-by metadata are included.

cache_hit is true only when input_hash matches. Customer id, if present on an order-line object, is not a column of any later artifact. No mart column is named customer_id.

Publication transaction

Assemble builds the row set in memory. Publish writes it in one database transaction: functional rows, contrast rows, KPI display rows, view rows, stage flags, and the run status. If the transaction does not commit, no functional is readable. There is no total row to write.

A functional that was not requested, withheld, or unidentified is inserted with value null, value_hex null, and the fixed identity string. A computed zero is status ok, value 0, value_hex of that zero, and a thin-data flag where required. A degraded F or H carries a non-null value. Status ok or degraded with a null value is a schema violation.

Unique key: (run_id, exposure_view, functional_code, regime, horizon).

Relational schema

CI and production use Postgres. Science values are double precision, which is float64. They are not numeric, because numeric cannot round-trip every float64 and the golden comparison would then disagree with a later GET. SQLite is not a CI target. value_hex is the IEEE-754 binary64 hex. value is the same bits rendered for display.

lock_hash is the lowercase hex SHA-256 of the canonical dependency preimage of the worker image: UTF-8, LF, no BOM, one line per distribution as name==version, sorted by name, final LF. It is not code_sha and it is not the seed-list hash. The API copies it from the release manifest at accept so the column is non-null before a worker starts. code_sha is null while queued. Publication of a terminal status requires code_sha not null.

Retention defaults, enforced later by a worker that writes an audit row in the same transaction as the delete: order-line Parquet 90 days, path samples 7 days, mart aggregates and series bins 1 year. After lines expire, the run still resolves the hashes, the policy version, the code SHA, and the lock hash. A rebuild is a new snapshot and a new run id. Backups must apply tombstones on restore. If the legal schedule differs, retention_schedule_id replaces these numbers. That override is not a silent change.

Grants are specified here and applied in Phase 4. The schema must already be compatible with them: no UPDATE of functional values, no UPDATE of policy.document, insert-only publication.

Exit criteria

Phase 2 is done when a forced mart error during publication leaves no functional visible, a withheld I is a null row with identity withheld:<reason>, G is stored as not_requested, the status checks reject a null ok value and reject a non-null withheld value, gross and netted cannot be written on the same row, and a schema test finds no total column. The golden E and F bits from Phase 1 can be inserted and read back as the same value_hex.
